# CS2 Tournament Organizator

Веб-панель для турниров и практик по CS2 в локальной сети компьютерного клуба.
Админы создают турниры, команды и серверы на сайте. Панель сама строит сетки, отправляет матчи на игровые серверы,
принимает от них результаты и продвигает сетку. Интерфейс на трёх языках: русский, английский, испанский.

> Статус проекта и то, что ещё не сделано или не проверено на живой игре, описаны в разделе [Ограничения и что не готово](#ограничения-и-что-не-готово).

## Как это устроено

```
 Игроки и админы (браузер)          Панель (Node.js, 1 процесс)              Игровые серверы CS2
 ───────────────────────►  сайт + API + SQLite  ──RCON (TCP)──►  cs2.exe -dedicated
                                         ▲                         + Metamod + CounterStrikeSharp
                                         └──HTTP: события матча────  + ArenaPro (плагин матчей)
```

- **Панель** (`server/` и `web/`) хранит турниры, команды, карты и серверы в SQLite-файле, строит сетки и раздаёт сайт.
- **Игровые серверы** — обычный CS2 (`cs2.exe -dedicated`) с плагином **ArenaPro** (наш форк MatchZy): паузы, бэкапы раундов, серии BO1/BO3/BO5, режим 2v2, запись демо.
- Панель управляет серверами по **RCON**. Матч передаётся ссылкой на конфиг: сервер сам забирает его с панели и присылает обратно события (начало карты, счёт, итог серии). Так результат попадает в сетку автоматически.

## Установка и запуск панели

Нужен **Node.js 24 или новее** (проверено на 26): панель использует встроенный `node:sqlite`. Docker не нужен.

```powershell
npm install
npm run build
.\start-panel.ps1 -PublicUrl 'http://192.168.0.4:3000'
```

`start-panel.ps1` собирает проект, если он ещё не собран, и запускает панель на порту 3000. Вместо скрипта можно:

```powershell
$env:PORT='3000'; $env:PUBLIC_URL='http://192.168.0.4:3000'; npm start
```

- **`PUBLIC_URL`** — адрес этого ПК в локальной сети (замените IP на свой). Он обязателен: по нему игровые серверы забирают конфиги матчей и присылают события, а Steam возвращает игрока после входа. Если оставить `localhost`, серверы на других ПК панель не увидят.
- Сайт открывается по этому адресу с любого ПК клуба.
- При первом запуске создаётся администратор. Логин `admin`, пароль выводится в консоль один раз. Запишите его (или задайте заранее, см. ниже).
- Остановить панель: `Ctrl+C` в окне, где она запущена.
- Данные лежат в `server/data/app.db`. Это единственный файл, который нужно копировать для резервной копии (панель при этом лучше остановить).

Для режима разработки: `npm run dev:server` и `npm run dev:web` (сайт на порту 5173 с проксированием запросов на сервер).

## Настройки

Задаются переменными окружения перед запуском:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт панели |
| `HOST` | `0.0.0.0` | На каких адресах слушать |
| `PUBLIC_URL` | `http://localhost:<PORT>` | Адрес панели в сети клуба (см. выше) |
| `DATA_DIR` | `./data` (относительно папки `server`) | Где лежит база данных |
| `ADMIN_PASSWORD` | случайный | Пароль первого администратора при самом первом запуске |

Секрет между панелью и игровыми серверами (токен событий) создаётся автоматически и хранится в базе. Вручную его вводить не нужно.

## Админ: логин и пароль

**Через сайт.** Войдите как админ, нажмите на свой логин в правом верхнем углу (страница «Аккаунт»). Там можно сменить логин и/или пароль. Нужно ввести текущий пароль, новый пароль не короче 8 символов.

**Через терминал** (если пароль забыт или нужен ещё один админ). Выполняйте из корня проекта; панель при этом можно не останавливать, но лучше сделать это при остановленной.

```powershell
npm run admin -- list                                  # показать логины
npm run admin -- set-password "новый-пароль"           # сменить пароль единственного админа
npm run admin -- set-password "новый-пароль" имя        # если админов несколько
npm run admin -- set-username старый новый             # сменить логин
npm run admin -- create логин пароль                   # создать ещё одного админа
```

Если панель запускалась с другим `DATA_DIR`, задайте его и для этой команды, иначе изменится не та база.

## Как пользоваться панелью

### Главная страница
Главная показывает то, что нужно прямо сейчас, и обновляется сама раз в несколько секунд.
- **Гость:** список идущих турниров и турниров с открытой регистрацией, кнопка входа через Steam.
- **Игрок:** «Мои матчи». Для каждого матча видно, что делать: пройти вето (карточка подсвечивается, когда ваш ход), дождаться сервера или подключиться: показывается команда `connect адрес:порт` с кнопкой «Копировать», карта и счёт идущего матча. Ниже турниры, на которые капитан может записать команду, турниры, где вы уже зарегистрированы, и ваши команды.
- **Админ:** «Требует внимания»: матчи, ожидающие вето, готовые матчи без свободного сервера или при выключенном автозапуске, ошибки запуска матчей, матчи на паузе, серверы с ошибками, групповой этап, после которого нужно сформировать плей-офф. Однотипные пункты одного турнира сводятся в одну строку. Рядом: состояние серверов (свободны, заняты, с проблемой), прогресс идущих турниров и быстрые кнопки.

### Игроки
1. Нажмите «Войти» → «Войти через Steam» (нужен интернет в клубе).
2. **Команды** → «Создать команду». Вы становитесь капитаном. Показывается код приглашения: отдайте его напарникам, они вводят его в поле «Вступить по коду».
3. Капитан может **назначить другого капитана**, исключать игроков и удалять команду.
4. **Турниры** → нужный турнир → «Зарегистрировать команду». Регистрирует капитан. Если в команде игроков больше, чем нужно для формата, капитан отмечает, кто играет.
5. **Вето карт.** Когда известны оба соперника, на карточке матча появляется ссылка «Вето карт». Капитаны открывают её со своего ПК и по очереди банят и пикают карты из пула, а после чужого пика выбирают сторону (CT или T). Первой ходит команда из верхнего слота матча. Пока вето не закончено, матч на сервер не уходит.
6. Когда матч запущен на сервере, на карточке матча виден адрес: `connect 192.168.0.4:27015`. Вставьте его в консоль игры (клавиша `~`).

Игроки видят сетку, таблицы групп и счёт идущих матчей.

### Администратор
1. **Карты.** Добавьте карты в библиотеку. Для Workshop-карты вставьте ссылку или ID: название и картинка подтянутся из Steam. Стандартные карты (`de_inferno`) добавляются вручную.
2. **Серверы.** Добавьте игровые серверы (см. [ниже](#игровые-серверы-и-как-они-работают)). Кнопка «Проверить» показывает, отвечает ли сервер и свободен ли он.
3. **Команды.** Админ может создать команду за игроков: название и до 10 игроков по **SteamID64** и нику. Первый игрок в списке станет капитаном. Когда этот человек войдёт через Steam, он автоматически окажется в своей команде. Здесь же можно добавлять и убирать игроков, назначать капитана, удалять команду.
4. **Турниры → «Создать турнир».** Название, размер команды (1v1 … 5v5), число команд, формат (см. [форматы](#форматы-турниров)), серия BO1/BO3/BO5 для каждого раунда сетки, **пул карт (до 7)**, галочка автозапуска матчей.
5. На странице турнира админ может **регистрировать любые команды** (даже без капитана) и снимать заявки.
6. **Рассадка до старта.** Номер перед командой — её сид. Кнопки ▲▼ меняют порядок, «Случайная рассадка» перемешивает. Ниже сразу показано, **как будет выглядеть сетка** (какой сид в какой точке, кто получает bye). Для групп показывается, в какие группы попадут команды.
7. **«Начать турнир».** Сетка и матчи создаются. Если включён автозапуск, готовые матчи сами уходят на свободные серверы.
8. **Во время турнира** на карточке матча:
   - «Запустить на сервере», если автозапуск выключен или нет свободного сервера.
   - «Пауза» / «Снять паузу».
   - «Переиграть карту» (текущая карта с первого раунда) и «Переиграть матч» (серия целиком, счёт сбрасывается).
   - На странице вето: «Завершить случайно» (за обе команды), «Начать вето заново», а также любой ход за любую команду. Недоступно после запуска матча на сервере.
   - Ручной ввод счёта и кнопки «Победа A/B» (назначить победителя без счёта, например при неявке или сбое).
   - «Отменить результат». Недоступно, пока сыграны следующие матчи: сначала отмените результаты следующих матчей.
9. **Групповой этап.** Когда все матчи групп сыграны, появляется панель «Плей-офф»: предложенный порядок сидов можно поменять, виден предпросмотр сетки, затем «Сформировать плей-офф». Пока в плей-офф нет сыгранных матчей, его можно отменить.

Язык интерфейса определяется по языку системы (русский, испанский, иначе английский). Переключатель языка в шапке сайта.

## Форматы турниров

**Плей-офф (сетка на выбывание):**
- **Single elimination.** Любое число команд, недостающие места заполняются bye (получают сильнейшие сиды).
- **Double elimination.** Верхняя и нижняя сетки, гранд-финал с переигровкой (отключается галочкой). На **2 командах** переигровка включена всегда: без неё чемпион мог бы определиться при счёте 1:1.

**Групповой этап перед плей-офф** (или самостоятельный):
- **Круговой турнир (очки).** Несколько групп, в каждой все играют со всеми. Победа 3 очка, поражение 0. Места: очки, затем личные встречи, разница карт, выигранные карты, коэффициент Бухгольца, сид. Если на границе прохода равенство определено только сидом, в таблице стоит «*», и панель предупреждает об этом перед плей-офф.
- **Швейцарская система.** Одна группа. Число туров по умолчанию: логарифм по основанию 2 от числа команд, вверх (можно задать своё). Пары строятся по очкам без повторных встреч. При нечётном числе команд самая слабая команда без bye получает свободный тур (засчитывается как победа). Следующий тур создаётся сам, когда сыгран предыдущий.
- **Double elimination в группе (GSL).** Группы по 4 команды: два стартовых матча, матч победителей, матч проигравших, решающий матч. Выходят две команды. Нужно ровно 4 команды на группу.

Выходят из группы столько команд, сколько вы укажете (для Swiss: сколько всего проходит дальше). Плей-офф строится «змейкой»: лучшие места всех групп идут первыми, соперники первого раунда из разных групп. Если плей-офф не нужен, победитель определяется по таблице (для одной группы).

Серия группового этапа (BO) и серии плей-офф по раундам задаются отдельно. Раунды плей-офф считаются с конца сетки, поэтому настройки остаются верными, даже если команд придёт меньше.

## Игровые серверы и как они работают

### Что это
Каждый «сервер» в панели — это один запущенный процесс CS2 (`cs2.exe -dedicated`) с плагином ArenaPro и открытым RCON.
Один процесс играет один матч одновременно. Для параллельных матчей нужно несколько процессов (разные порты).

Панель работает с серверами так:
1. Когда матч готов (известны обе команды), панель берёт свободный сервер и по RCON выполняет `arenapro_loadmatch_url` со ссылкой на конфиг матча (`PUBLIC_URL/api/arenapro/config/<id>`).
2. Сервер забирает конфиг: команды, SteamID игроков, карты, режим 2v2 (Wingman), адрес и ключ для событий. Игроки закрепляются за своими командами по SteamID.
3. Панель проверяет, что сервер подтвердил матч (`get5_status`). Если нет, матч возвращается в очередь, а сервер на 30 секунд откладывается.
4. Во время игры сервер присылает на панель события, а панель показывает счёт и карту. В конце серии приходит итог: сетка продвигается, сервер освобождается, и следующий готовый матч уходит на него.
5. Раз в 10 секунд панель повторно раздаёт ожидающие матчи.

> **Серверы, добавленные в панель, считаются её собственными.** Перед загрузкой матча панель завершает всё, что шло на сервере (`get5_endmatch`). Не используйте один и тот же сервер для ручных игр и для панели.

### Как поднять сервер
Пример готовой установки — папка `D:\cs2-server` на ПК с серверами (игра, SteamCMD и скрипт запуска `start-test-server.ps1`). Порядок такой:

1. **Игра.** Скачайте CS2 через SteamCMD в отдельную папку (не в игровую папку Steam):
   `steamcmd +force_install_dir D:\cs2-server\cs2 +login anonymous +app_update 730 validate +quit`.
   Либо скопируйте уже установленную игру и выполните `app_update 730 validate`. Отдельного «серверного» пакета у CS2 нет: тот же файл `cs2.exe` запускается с ключом `-dedicated`.
2. **Metamod:Source 2.0**, **CounterStrikeSharp** (сборка with-runtime для Windows) и **ArenaPro**: распаковать в `game\csgo`. В `game\csgo\gameinfo.gi` в блоке `SearchPaths` добавьте строку `Game csgo/addons/metamod` **перед** `Game csgo`.
   Исходники плагина лежат в папке `plugin/` этого репозитория. Сборка и установка на сервер: `npm run plugin:build` (пакет в `plugin-dist/`) или `.scriptsuild-plugin.ps1 -DeployTo "D:cs2-servercs2gamecsgo"` (сервер перед этим остановите). Порядок обновления с оригинального MatchZy описан в `plugin/tools/UPDATING.md`, наши правки поверх переименования — в `plugin/PATCHES.md`.
3. **Запуск.** Пример (подставьте свой IP, порт и RCON-пароль):

   ```powershell
   cs2.exe -dedicated -console -condebug -usercon -insecure -ip 192.168.0.4 -port 27015 `
       +sv_lan 1 +rcon_password ПАРОЛЬ +game_type 0 +game_mode 2 +map de_inferno
   ```

   - `-usercon` включает RCON по TCP. Без него панель не сможет управлять сервером.
   - `-ip` привязывает сервер к адресу в локальной сети. Без него CS2 может привязаться к другому адаптеру (например, VPN).
   - `-insecure` и `+sv_lan 1` — режим локальной сети без VAC и без токена Steam.
   - `-authkey <ключ Steam Web API>` нужен для скачивания Workshop-карт. Ключ создаётся на `steamcommunity.com/dev/apikey`. В нашем скрипте `start-test-server.ps1` ключ читается из файла `authkey.txt` рядом (в Git он не попадает).
4. **Панель → «Серверы» → добавить:** название, адрес, порт, RCON-пароль. Нажмите «Проверить».
5. Для нескольких серверов запускайте несколько процессов из одной установки с разными `-port` (27015, 27016, …) и добавьте каждый в панель.
   Если включаете GOTV, дайте каждому серверу свой `+tv_port`. Общий файл статистики ArenaPro между экземплярами из одной папки на практике не проверялся: при проблемах используйте отдельные копии установки.

### Типичные проблемы
- **«Отказано в доступе» при запуске `cs2.exe`** — у нас это вызывал запущенный **FACEIT Anti-Cheat**. Закройте клиент FACEIT (и при необходимости перезагрузите ПК) перед запуском сервера.
- **Сервер «не подтвердил загрузку матча»** — проверьте `PUBLIC_URL` (панель должна открываться с этого ПК по этому адресу), брандмауэр на порту панели и то, что в ArenaPro нет уже загруженного чужого матча.
- **Игра при подключении к серверу пишет «Unable to establish server connection», а сервер падает.** После обновления CS2 плагины иногда несовместимы. Мы встречали такое с CounterStrikeSharp 1.0.376 при CS2 1.41.9.4. Помогло обновление CounterStrikeSharp. Перед каждым турниром подключайтесь к серверу и проверяйте его заранее.
- **Версии должны совпадать.** CS2 на серверах и на игровых ПК должен быть одной сборки. Клиенты обновляются через Steam сами, серверы через `app_update 730`.

## Ограничения одного компьютера клуба

Расчёты ниже основаны на конфигурации Ryzen 7 7800X3D, 32 ГБ ОЗУ и 25 ПК в клубе. Это **оценки, а не замеры**: точное число серверов нужно проверить нагрузочным запуском.

- **Процессор — главный предел.** Основной поток сервера CS2 занимает примерно одно ядро. У 7800X3D 8 физических ядер: с учётом панели и системы разумно **5–6 серверов 2v2 или до 2 серверов 5v5** на одном выделенном ПК (при 2v2 нагрузка на сервер заметно ниже, чем при 5v5, возможно до 7–8).
- **Память.** Около 2–4 ГБ на сервер (больше с Workshop-картами). 32 ГБ хватает на 8 и более серверов, но не на запас сверх процессора.
- **Диск.** Установка CS2 около 70 ГБ. Несколько серверов запускаются из одной установки, повторно качать не нужно.
- **Сеть.** Нагрузка в LAN ничтожна. Нужен статический IP у ПК с панелью и серверами.
- **Не размещайте серверы на ПК, за которыми играют.** Клиент CS2 сам загружает процессор, и сервер начинает терять тики (в логе сервера «Long frame»). Лучше выделить отдельный ПК под панель и серверы.
- **Арифметика четверга.** 12 команд 2v2 — это 24 игрока. В клубе 25 ПК: 24 игровых и 1 выделенный под серверы и панель. Запас по местам — одно место. Если админы тоже играют, игровых мест не хватит. Админы управляют с телефона или ноутбука через сайт.
- **Сколько матчей идёт одновременно.** В группах и в Swiss на 12 команд сразу 6 матчей, то есть 6 серверов. В сетке на выбывание одновременных матчей обычно меньше из-за bye. Это верхняя граница, на которую рассчитана одна машина. Если свободных серверов не хватает, матчи ждут очереди (панель раздаёт их сама, как только сервер освободится).
- **Единая точка отказа.** Панель, база и серверы на одном ПК: перезагрузка или поломка останавливает всё. Делайте резервную копию `server/data/app.db` перед турниром.
- **Обновления CS2** выходят без предупреждения и могут сломать плагины. Не обновляйте серверный ПК в день турнира и проверьте всё заранее.
- **Вход через Steam** требует интернета в клубе. Без интернета игроков можно регистрировать вручную (админ создаёт команды по SteamID64), но Workshop-карты и Steam-вход работать не будут.

## Ограничения и что не готово

- **Вето карт.** Порядок (пул 7 карт): BO1 шесть банов и оставшаяся карта на ноже; BO3 бан, бан, пик, пик, бан, бан, решающая на ноже; BO5 бан, бан, четыре пика, решающая на ноже. После пика соперник выбирает сторону. Жребия нет: первой всегда ходит команда из верхнего слота. Таймера на ход пока нет, зависшее вето админ завершает кнопкой «Завершить случайно». Вето можно отключить галочкой при создании турнира: тогда берутся первые карты пула, стороны решает нож. Не проверено: вето с Workshop-картами на реальном сервере.
- **Живая игра проверена не полностью.** Проверены: загрузка матча на сервер, подключение игрока, паузы, приём событий в тестах. Не проверены на реальной серии: автоматический итог серии с сервера, «Переиграть карту» (использует бэкап нулевого раунда `css_restore 0`), работа с Workshop-картами, режим 1v1.
- Матчи не берут демо (запись демо включается настройками ArenaPro, панель их пока не собирает).
- Нет HTTPS: панель рассчитана на локальную сеть клуба. Не выставляйте её в интернет.
- Нет защиты от перебора пароля админа.
- Лицензия проекта не выбрана. Плагин ArenaPro — форк MatchZy (MIT), авторство и лицензия сохранены в его репозитории (`LICENSE`, `NOTICE.md`).

## Разработка

```powershell
npm test -w server            # тесты движка сеток и групп (28 тестов)
npm run build                 # сборка сайта и сервера
npm run dev:server            # сервер с перезапуском при изменениях
npm run dev:web               # сайт в режиме разработки
npm run plugin:test           # тесты плагина (dotnet)
npm run plugin:build          # сборка пакета плагина в plugin-dist/
```

Структура:

| Путь | Что внутри |
|---|---|
| `server/src/bracket.ts` | Движок плей-офф: single/double elimination, bye, отмена и назначение результата |
| `server/src/groups.ts` | Круговой турнир, Swiss, GSL, таблицы, посев в плей-офф |
| `server/src/groupStage.ts` | Жизненный цикл групп и переход к плей-офф |
| `server/src/veto.ts` | Вето карт: шаблоны BO1/BO3/BO5, баны, пики, стороны |
| `server/src/dispatcher.ts` | Раздача матчей по серверам, RCON |
| `server/src/routes/` | HTTP API (тут же приём событий серверов) |
| `server/src/rcon.ts` | RCON-клиент для CS2 |
| `plugin/` | Исходники плагина ArenaPro (форк MatchZy, C#), инструменты обновления с оригинала |
| `scripts/build-plugin.ps1` | Сборка плагина и установка на сервер |
| `server/scripts/admin.ts` | Управление админами из терминала |
| `web/src/` | Сайт (React). Переводы в `web/src/locales/` |
| `PLAN.md` | План разработки и результаты проверок сервера |

Ошибки API передаются кодами (`{"error":"badCredentials"}`), а текст на нужном языке подставляет сайт. При добавлении сообщения добавьте ключ `e.<код>` во все три словаря: `ru.ts`, `en.ts`, `es.ts` (TypeScript не даст собрать проект, если в каком-то языке ключа нет).
