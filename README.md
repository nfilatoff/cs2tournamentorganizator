# CS2 Tournament Organizator

Веб-панель для проведения турниров Counter-Strike 2 в локальной сети: компьютерном клубе, на LAN-вечеринке, в учебном заведении или офисе. Она объединяет в одном месте регистрацию команд, турнирную сетку, вето карт и управление выделенными серверами CS2, поэтому организатору не нужно вручную вводить в консоль сервера команды, составы и счёт.

Интерфейс доступен на русском, английском и испанском языках.

## Для чего нужен проект

Даже небольшой турнир по CS2 требует много ручной работы. Нужно собрать команды, составить сетку, провести вето, загрузить на сервер нужную карту и составы, следить за паузами, записать результат и запустить следующий матч. Когда одновременно идут несколько матчей на разных серверах, организатор легко ошибается.

Панель берёт эту рутину на себя:

- игроки сами входят через Steam, собирают команды и регистрируются в турнире;
- сетка строится автоматически и продвигается по результатам матчей;
- капитаны проводят вето карт со своих компьютеров в браузере;
- готовые матчи сами распределяются по свободным игровым серверам;
- сервер с плагином ArenaPro следит за составами, ножевым раундом, готовностью и паузами, а после матча отправляет результат в панель.

Проект рассчитан на один выделенный компьютер с Windows, на котором работают и панель, и несколько процессов сервера CS2. Docker, отдельный сервер базы данных и облачные сервисы не нужны. Интернет требуется только для установки, входа игроков через Steam и загрузки превью карт.

## Как это работает

```text
 Браузеры игроков и администратора
              │  HTTP (адрес панели в LAN)
              ▼
 ┌──────────────────────────┐   RCON: загрузить матч, пауза, смена карты
 │  Панель (Node.js)        │ ───────────────────────────────────────────┐
 │  сайт + API + SQLite     │                                            ▼
 │                          │ ◄──── события матча ──── ┌──────────────────────────────┐
 └──────────────────────────┘   (HTTP, токен матча)    │ CS2 dedicated server         │
              ▲                                        │ Metamod + CounterStrikeSharp │
              └──── конфигурация матча (JSON) ──────── │ + плагин ArenaPro            │
                                                       └──────────────────────────────┘
```

1. Администратор создаёт турнир, а панель строит сетку.
2. Когда у матча известны обе команды и вето завершено, панель выбирает свободный сервер и по RCON передаёт ему адрес конфигурации матча.
3. ArenaPro скачивает конфигурацию с панели: команды, игроков по SteamID, карты, формат серии, лимиты пауз. Затем он запускает разминку и ожидает готовности игроков.
4. Во время игры плагин отправляет панели события: начало карты, счёт раундов, конец карты и конец серии.
5. После окончания серии панель записывает результат, продвигает победителя по сетке и отправляет следующий матч на освободившийся сервер.

Проект состоит из трёх частей:

| Часть | Папка | Технологии |
| --- | --- | --- |
| Сервер панели (API, сетки, вето, раздача матчей, RCON) | `server/` | Node.js 24, TypeScript, Fastify, SQLite |
| Веб-интерфейс | `web/` | React, Vite |
| Плагин игрового сервера ArenaPro | `plugin/` | C#, .NET 10, CounterStrikeSharp |

ArenaPro — это доработанный для панели плагин матчей на основе MatchZy. Он поддерживает интеграцию с панелью, лимиты пауз и формат событий, который ожидает панель. Обычный MatchZy вместо него не подойдёт.

## Возможности

**Турниры**

- Сетки single elimination и double elimination.
- Групповые этапы: круговой (round robin), швейцарская система и GSL, с последующим плей-офф или без него.
- Серии BO1, BO3 и BO5.
- Вето карт, которое капитаны проводят на сайте до отправки матча на сервер.
- Лимиты пауз на карту для каждой команды: число и длительность тактических пауз (`.tac`) и число технических пауз (`.tech`).
- Ручной ввод результата и ручной запуск матча на выбранном сервере, если что-то пошло не по плану.

**Команды и игроки**

- Вход игроков через Steam. Ник берётся из Steam, его можно переопределить в профиле или в панели администратора.
- Создание команды и вступление по коду приглашения. Капитан регистрирует команду в открытом турнире.
- Администратор может создавать команды и добавлять их в турнир прямо со страницы турнира.
- После запуска матча на главной странице игрока появляется готовая команда подключения, например `connect 192.168.0.4:27015`.

**Серверы**

- Подключение любого количества процессов CS2 и проверка их состояния через RCON.
- Запуск, перезапуск и остановка серверов CS2 на компьютере с панелью прямо из интерфейса. Можно настроить стартовую карту, режим, слоты, GOTV, пароль и дополнительные команды.
- Автоматическая раздача готовых матчей по свободным серверам. Если сервер не подтвердил загрузку матча, панель временно исключает его из раздачи.

**Карты**

- Библиотека карт со стандартным набором. Превью официальных карт загружаются автоматически.

## Установка

Подробная инструкция находится в [INSTALLATION.md](INSTALLATION.md). Как проводить тренировки (раскидка гранат, боты) и товарищеские матчи без турнира, описано в [PRACTICE.md](PRACTICE.md). Коротко, установить всё можно двумя способами.

**Автоматически.** Скачайте один файл [install-cs2.ps1](https://raw.githubusercontent.com/nfilatoff/cs2tournamentorganizator/main/install-cs2.ps1) и запустите его из PowerShell x64 от имени администратора:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-cs2.ps1 -InstallRoot 'E:\LAN Server'
```

Скрипт сам скачает Git, Node.js, .NET SDK, SteamCMD, отдельную серверную копию CS2, Metamod, CounterStrikeSharp и ArenaPro. Затем он соберёт панель, создаст базу с администратором и сервером, настроит брандмауэр и создаст файлы запуска. Папку установки нужно выбирать на том же диске, где установлена CS2. Повторный запуск восстанавливает недостающие компоненты и сохраняет аккаунты, пароли и конфиги, а с ключом `-Update` обновляет панель и ArenaPro до последней версии с GitHub (см. [«Обновление»](INSTALLATION.md#обновление)). Перед повторным запуском остановите сервер и панель.

**Вручную.** Если скрипт не подходит или завершается с ошибкой, все шаги можно выполнить самостоятельно. Порядок описан в разделе [«Ручная установка»](INSTALLATION.md#ручная-установка-с-нуля).

## Как пользоваться

Ниже описан типичный порядок работы: от подготовки до окончания турнира.

### 1. Подготовка (администратор)

1. Запустите панель и игровой сервер. После установки скриптом это делают `start-panel.ps1` и `start-server.ps1` из папки установки (см. [INSTALLATION.md](INSTALLATION.md#запуск-после-установки)).
2. Откройте адрес панели в браузере: он указан в `credentials.txt` и печатается при запуске панели (строка `Panel URL`), например `http://192.168.0.4:3000`. Войдите как `admin` с паролем из `credentials.txt` или из консоли первого запуска. Сразу смените пароль в разделе «Аккаунт».
3. В разделе «Серверы» убедитесь, что сервер добавлен, и нажмите «Проверить»: панель должна получить его состояние по RCON. При необходимости добавьте ещё серверы (см. [«Управление серверами»](#управление-серверами)).
4. В разделе «Карты» проверьте пул карт. Стандартные карты добавляются при первом запуске с пустой базой.

### 2. Создание турнира

1. Откройте «Турниры» и создайте новый турнир.
2. Выберите формат: сетку (single/double elimination) или групповой этап (round robin, швейцарская система, GSL), а для групп при необходимости последующий плей-офф.
3. Задайте серии BO1/BO3/BO5, пул карт и включите вето, если капитаны должны выбирать карты сами.
4. Задайте лимиты пауз на карту: число и длину тактических пауз и число технических (0 — без ограничения). Позже лимиты можно изменить на странице турнира. Новые значения действуют для матчей, запущенных после изменения.
5. Откройте регистрацию. Команды можно добавить вручную на странице турнира или дождаться, пока капитаны зарегистрируются сами.

### 3. Регистрация (игроки)

1. Игрок открывает адрес панели и входит через Steam. Для этого нужен интернет.
2. Один игрок создаёт команду и становится капитаном. Остальные вступают в неё по коду приглашения.
3. Капитан регистрирует команду в открытом турнире.

### 4. Проведение турнира

1. Когда команды собраны, администратор начинает турнир, и панель строит сетку.
2. Если вето включено, капитаны обеих команд открывают страницу матча и по очереди банят и выбирают карты.
3. Когда матч готов, панель отправляет его на свободный сервер (при включённом автозапуске) или администратор запускает его вручную на нужном сервере.
4. На странице матча (ссылка с главной страницы, из сетки и со страницы вето) игроки видят сервер, команду `connect ...`, кнопку подключения через Steam, кто из игроков уже на сервере и сколько осталось времени. ArenaPro распределяет игроков по командам по SteamID.
5. Когда команда в сборе, её капитан пишет в чат `.ready`. После `.ready` обоих капитанов идёт отсчёт 10 секунд, затем рестарт и матч (с ножевым раундом, если сторона не выбрана в вето). Паузы берутся командами `.tac` и `.tech` в пределах лимитов турнира.
6. На подключение даётся 10 минут с момента запуска матча на сервере. Если матч за это время не начался, победа присуждается команде, у которой больше игроков на сервере; если поровну, победителя выбирает жребий, и она проходит дальше по сетке. В сетке такой матч помечен как неявка.
6. После окончания серии результат приходит в панель автоматически, сетка обновляется, и следующий матч уходит на освободившийся сервер.
7. Если что-то пошло не так (сервер упал, матч сыгран без панели), администратор может ввести результат вручную.

## Управление серверами

Каждый параллельный матч требует отдельного процесса CS2 со своим портом. Есть два способа подключить серверы.

### Запуск серверов из панели

Если CS2 установлена на том же компьютере, что и панель, процессы можно запускать прямо из интерфейса. В разделе «Серверы»:

1. В блоке «Запуск серверов на этом компьютере» укажите папку выделенного сервера CS2 (ту, где лежит `game\bin\win64\cs2.exe`). После установки через `install-cs2.ps1` папка `cs2` находится автоматически. Её также можно задать переменной окружения `CS2_PATH`.
2. Добавьте сервер с отметкой «Запускать из панели на этом компьютере». Адрес, порт и RCON-пароль можно не заполнять: панель подставит адрес `auto`, следующий свободный порт и случайный пароль.
3. В «Настройках» сервера задайте стартовую карту, режим, число слотов, GOTV, имя сервера, пароль для входа, токен GSLT и дополнительные команды cfg. Кнопки «Запустить», «Перезапустить» и «Остановить» управляют процессом, а «Сменить карту сейчас» меняет карту по RCON. Отметка «Запускать вместе с панелью» поднимает сервер при старте панели.

Панель пишет для каждого сервера файл `game\csgo\cfg\tournament-panel\server-<id>.cfg` и запускает `cs2.exe` в отдельном окне. Процесс продолжает работать после перезапуска панели. Остановить его можно той же кнопкой (через RCON `quit`). Сервер, на котором идёт матч, панель не останавливает. Порт GOTV по умолчанию равен порту сервера плюс 100.

Для каждого нового порта разрешите входящий трафик в брандмауэре Windows. Команды выполняются в PowerShell от имени администратора, порт замените своим:

```powershell
New-NetFirewallRule -DisplayName 'CS2 27016' -Direction Inbound -Protocol UDP -LocalPort 27016 -Action Allow
New-NetFirewallRule -DisplayName 'CS2 RCON 27016' -Direction Inbound -Protocol TCP -LocalPort 27016 -Action Allow
```

### Адрес панели и серверов

Постоянный IP компьютеру с панелью не нужен. При каждом запуске панель сама определяет свой адрес в локальной сети: берётся адаптер, через который идёт маршрут по умолчанию, поэтому VPN (Radmin, Hamachi) и виртуальные адаптеры Hyper-V не мешают. Если адрес изменится во время работы (DHCP, другой роутер), панель подхватит его в течение 30 секунд. Текущий адрес панель печатает при запуске в строке `Panel URL`.

У сервера CS2 на этом же компьютере адрес `auto`. Игрокам показывается текущий IP компьютера, а сама панель подключается к серверу по RCON и подключается к нему по этому же адресу (сервер запускается с `-ip` текущего LAN-адреса). После смены IP компьютера перезапустите серверы. Для сервера на другом компьютере укажите его IP.

Вход через Steam возвращает игрока на тот адрес, по которому он открыл сайт. Закрепить адрес вручную (например, имя хоста вместо IP) можно переменной `PUBLIC_URL` или параметром `-PublicUrl` скрипта запуска.

### Серверы, запущенные вручную

Сервер можно запустить вручную на этом или на другом компьютере сети (как это сделать, см. [INSTALLATION.md](INSTALLATION.md#10-первый-запуск-игрового-сервера)). Затем в разделе «Серверы» добавьте его имя, IP, порт и RCON-пароль. Кнопка «Проверить» запрашивает состояние сервера через RCON.

Второй сервер на том же компьютере запускается тем же `cs2.exe` с другим портом, например `27016`, и добавляется в панель отдельно. Если используется GOTV, каждому процессу нужен свой `+tv_port`. Перед турниром проверьте, что все процессы и плагин работают одновременно.

### Важно знать

- Панель считает добавленные серверы своими: перед загрузкой следующего матча она отправляет `get5_endmatch`. Не используйте эти процессы одновременно для ручных матчей.
- Если сервер не подтвердил загрузку, матч снова становится готовым к запуску, а сервер временно исключается из раздачи.
- Игровые серверы на других компьютерах должны иметь доступ к адресу панели: по нему они получают конфигурации матчей и отправляют события.

### Если сервер не отвечает

- Проверьте, что `cs2.exe` запущен, IP и порт в панели совпадают с параметрами процесса, а RCON-пароль введён верно.
- Для сервера на другом компьютере проверьте, что адрес панели (строка `Panel URL` при её запуске) открывается с этого компьютера и что брандмауэр пропускает порт панели.
- В консоли сервера выполните `meta list` и `css_plugins list`: должны быть загружены CounterStrikeSharp и ArenaPro.
- После обновления CS2 проверьте совместимость Metamod, CounterStrikeSharp и ArenaPro и сыграйте тестовый матч до турнира.

## Настройка и обслуживание панели

### Запуск панели из репозитория

Нужны Node.js 24 или новее и npm. В Windows PowerShell используйте `npm.cmd`: этот файл запускается и при стандартной политике, которая блокирует `npm.ps1`. Команды выполняются из корня репозитория:

```powershell
npm.cmd ci
npm.cmd run build
.\start-panel.ps1
```

Адрес панели в сети определяется сам и печатается при запуске. Для остановки панели нажмите `Ctrl+C` в её окне PowerShell.

`start-panel.ps1` пересобирает проект перед запуском. Его параметры: `-Port` (по умолчанию `3000`), `-DataDir`, `-Cs2Path`, `-PublicUrl` (только чтобы закрепить адрес) и `-NoBuild`. После сборки панель можно запустить и без скрипта:

```powershell
$env:PORT = '3000'
npm.cmd start
```

### Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3000` | Порт панели |
| `HOST` | `0.0.0.0` | Адрес, на котором слушает сервер |
| `PUBLIC_URL` | Определяется сам: `http://<LAN-адрес>:<PORT>` | Закреплённый адрес панели для игроков, серверов на других компьютерах и входа через Steam |
| `DATA_DIR` | `server/data` при запуске через npm | Каталог файла `app.db` и превью карт |
| `ADMIN_PASSWORD` | Случайный пароль | Пароль `admin` только при создании первой учётной записи |
| `CS2_PATH` | — | Папка выделенного сервера CS2 для запуска серверов из панели |

При первом запуске с пустой базой создаётся администратор `admin`. Случайный пароль выводится в консоль один раз. Изменение `ADMIN_PASSWORD` после первого запуска не меняет пароль существующего администратора.

### Резервная копия

База по умолчанию находится в `server/data/app.db`, а при установке скриптом — в `<папка установки>\data\app.db`. Если задан `DATA_DIR`, база находится в нём. Для резервной копии остановите панель и скопируйте этот файл (или всю папку данных).

### Восстановление доступа администратора

Из корня репозитория (при установке скриптом — из папки `panel`):

```powershell
npm.cmd run admin -- list
npm.cmd run admin -- set-password 'новый-пароль'
npm.cmd run admin -- set-password 'новый-пароль' логин
npm.cmd run admin -- set-username старый_логин новый_логин
npm.cmd run admin -- create логин 'пароль-не-короче-8-символов'
```

Команда `set-password` без логина работает, только если администратор один. Если панель использует нестандартный `DATA_DIR`, задайте тот же каталог перед запуском этих команд.

### Превью карт

Превью официальных карт панель скачивает при первом показе из репозитория [cs2-map-images](https://github.com/ghostcap-gaming/cs2-map-images) и хранит в `DATA_DIR\map-images`. Без интернета показывается заглушка с названием карты.

## Текущие ограничения

- Автоматическая обработка полной серии на реальном сервере, Workshop-карты и режим 1v1 не проверены сквозным игровым тестом. Перед турниром проведите пробный матч на своей конфигурации.
- Панель не собирает демозаписи. Их запись зависит от настройки ArenaPro.
- Панель рассчитана на локальную сеть: в проекте нет настройки HTTPS и защиты входа администратора от перебора пароля. Не публикуйте её напрямую в интернете.
- Число одновременных серверов зависит от оборудования и режима матчей, поэтому нагрузку нужно проверить на конкретном ПК. Каждый параллельный матч требует отдельного процесса CS2.

## Разработка

```powershell
npm.cmd run dev:server     # API с перезапуском при изменениях
npm.cmd run dev:web        # Vite на порту 5173

```

### Панель из репозитория на компьютере разработчика

На компьютере, где ведётся разработка, панель работает прямо из репозитория, а отдельная папка (например, `D:\cs2-server`) нужна только для серверной CS2. Копия проекта в `<папка установки>\panel`, которую создаёт `install-cs2.ps1`, предназначена для компьютера в клубе.

Настройки этого компьютера хранятся в `panel.local.json` в корне репозитория (файл не попадает в git):

```json
{
  "Port": 3100,
  "DataDir": "server\\data-live",
  "Cs2Path": "D:\\cs2-server\\cs2"
}
```

`.\start-panel.ps1` пересобирает панель и запускает её с этими настройками. Параметры командной строки (`-Port`, `-PublicUrl`, `-DataDir`, `-Cs2Path`) важнее файла, `-NoBuild` пропускает сборку. После изменений плагина остановите игровой сервер и установите новую сборку:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-plugin.ps1 -DeployTo 'D:\cs2-server\cs2\game\csgo'
```

Структура репозитория:

| Путь | Содержимое |
| --- | --- |
| `server/src/` | API, сетки (`bracket.ts`, `groups.ts`), вето, раздача матчей (`dispatcher.ts`), RCON, запуск процессов CS2 |
| `web/src/` | Интерфейс, страницы и переводы (`locales/`) |
| `plugin/` | Исходники ArenaPro, его конфиги и тесты |
| `scripts/build-plugin.ps1` | Сборка и установка ArenaPro на сервер |
| `scripts/test-installer.ps1` | Offline-проверки установщика |
| `install-cs2.ps1` | Установщик (описание в INSTALLATION.md) |
| `PRACTICE.md` | Тренировки и товарищеские матчи: команды ArenaPro в игре |

`global.json` выбирает стабильный .NET SDK 10 с установленным обновлением. В `package.json` закреплены исправленные версии `glob/minimatch`, пока `@fastify/static` использует более старую ветку, и разрешён установочный скрипт `esbuild@0.28.2`, необходимый для сборки. При обновлении esbuild это разрешение нужно пересмотреть. Проверка зависимостей: `npm.cmd audit` и `dotnet list plugin/ArenaPro.csproj package --vulnerable --include-transitive`.

Если NuGet-зависимости уже восстановлены, пакет плагина можно собрать без обращения к NuGet: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-plugin.ps1 -NoRestore`. При ошибке сборки предыдущий пакет `plugin-dist` сохраняется.
