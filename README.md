# CS2 Tournament Organizator

Панель для турниров CS2 в локальной сети. Администратор создаёт команды и турниры, подключает игровые серверы. Панель хранит данные в SQLite, управляет серверами через RCON и принимает события матчей от плагина ArenaPro. Интерфейс доступен на русском, английском и испанском языках.

## Полная установка на Windows

Скачайте [install-cs2.ps1](https://raw.githubusercontent.com/nfilatoff/cs2tournamentorganizator/main/install-cs2.ps1) и запустите из PowerShell x64 от имени администратора:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-cs2.ps1 -InstallRoot 'E:\LAN Server'
```

Замените путь на новую или пустую папку **на том же диске, где установлена CS2**. Если не указывать `-InstallRoot`, скрипт предложит выбрать папку или букву диска. Он сам скачает Git, клонирует этот репозиторий в подпапку `panel`, установит отдельный сервер CS2 в `cs2`, зависимости и ArenaPro, соберёт панель и создаст файлы запуска. При недостатке места установка отменяется до загрузок. Для проверки без установки добавьте `-CheckOnly`.

Переносить весь проект не требуется — достаточно одного файла скрипта. [Подробная инструкция и параметры](install-cs2.txt).

## Запуск панели

Нужны Node.js 24 или новее и npm. В Windows PowerShell используйте `npm.cmd`: этот файл запускается и при стандартной политике, блокирующей `npm.ps1`. Выполняйте команды из корня этого репозитория:

```powershell
npm.cmd ci
npm.cmd run build
.\start-panel.ps1 -PublicUrl 'http://192.168.0.4:3000'
```

Замените `192.168.0.4` на IP компьютера с панелью в вашей сети и откройте этот адрес в браузере. Игровые серверы должны иметь доступ к `PUBLIC_URL`: по нему они получают конфигурации матчей и отправляют события. Адрес также используется для возврата после входа через Steam.

При первом запуске создаётся администратор `admin`. Случайный пароль выводится в консоль один раз. Запишите его и смените в разделе «Аккаунт». Для остановки панели нажмите `Ctrl+C` в её окне PowerShell.

`start-panel.ps1` собирает проект, если сборки ещё нет. Его параметры: `-Port` (по умолчанию `3000`), `-PublicUrl` и `-DataDir`. Без `-PublicUrl` скрипт подставляет `http://192.168.0.4:<порт>`, поэтому для другого IP укажите адрес явно. После сборки панель можно запустить и без скрипта:

```powershell
$env:PORT = '3000'
$env:PUBLIC_URL = 'http://192.168.0.4:3000'
npm.cmd start
```

База по умолчанию находится в `server/data/app.db`. Для резервной копии остановите панель и скопируйте этот файл. Если задан `DATA_DIR`, база находится в нём.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3000` | Порт панели |
| `HOST` | `0.0.0.0` | Адрес, на котором слушает сервер |
| `PUBLIC_URL` | `http://localhost:<PORT>` | Адрес панели для браузеров, игровых серверов и входа через Steam |
| `DATA_DIR` | `server/data` при запуске через npm | Каталог файла `app.db` |
| `ADMIN_PASSWORD` | Случайный пароль | Пароль `admin` только при создании первой учётной записи |

Изменение `ADMIN_PASSWORD` после первого запуска не меняет пароль существующего администратора.

### Восстановление доступа администратора

Из корня репозитория:

```powershell
npm.cmd run admin -- list
npm.cmd run admin -- set-password 'новый-пароль'
npm.cmd run admin -- set-password 'новый-пароль' логин
npm.cmd run admin -- set-username старый_логин новый_логин
npm.cmd run admin -- create логин 'пароль-не-короче-8-символов'
```

Команда `set-password` без логина работает, только если администратор один. Если панель использует нестандартный `DATA_DIR`, задайте тот же каталог перед запуском этих команд.

## Подключение игрового сервера

Каждый игровой сервер — отдельный процесс CS2 с Metamod:Source, CounterStrikeSharp и ArenaPro. Панель не устанавливает и не запускает CS2: подготовьте сервер отдельно.

1. Установите CS2 через SteamCMD. Пример для папки `D:\cs2-server\cs2`:

   ```powershell
   & 'D:\cs2-server\steamcmd\steamcmd.exe' +force_install_dir D:\cs2-server\cs2 +login anonymous +app_update 730 validate +quit
   ```

   Если SteamCMD находится в другой папке, замените путь к `steamcmd.exe`.

2. Установите Metamod:Source и CounterStrikeSharp для Windows в `D:\cs2-server\cs2\game\csgo`. В файле `game\csgo\gameinfo.gi` добавьте `Game csgo/addons/metamod` в блок `SearchPaths` перед `Game csgo`.
3. Соберите ArenaPro из папки `plugin/` и установите его в ту же папку `game\csgo`. Перед установкой остановите игровой сервер:

   ```powershell
   .\scripts\build-plugin.ps1 -DeployTo 'D:\cs2-server\cs2\game\csgo'
   ```

   Скрипт создаёт пакет в `plugin-dist/` и копирует его на сервер. Для сборки нужен .NET SDK. Если игра установлена в другом месте, замените путь после `-DeployTo`. Для сборки пакета без установки используйте `npm run plugin:build`.

4. Запустите сервер в отдельном окне PowerShell. Указывайте **полный путь к `cs2.exe`**: команда `cs2.exe` сама по себе не находится из произвольной папки, например `C:\WINDOWS\system32`.

   ```powershell
   & 'D:\cs2-server\cs2\game\bin\win64\cs2.exe' -dedicated -console -condebug -usercon -insecure -ip 192.168.0.4 -port 27015 `
       +sv_lan 1 +rcon_password 'СВОЙ_ПАРОЛЬ' +game_type 0 +game_mode 2 +map de_inferno
   ```

   Замените IP на адрес компьютера с **игровым сервером** и задайте свой RCON-пароль. `-usercon` нужен для управления по RCON. Пример рассчитан на игру в локальной сети.

5. В панели откройте «Серверы», добавьте имя, IP, порт и тот же RCON-пароль. Кнопка «Проверить» запрашивает состояние сервера через RCON.

### Второй и следующие сервера на том же компьютере

Откройте ещё одно окно PowerShell и запустите тот же `cs2.exe` с другим портом:

```powershell
& 'D:\cs2-server\cs2\game\bin\win64\cs2.exe' -dedicated -console -condebug -usercon -insecure -ip 192.168.0.4 -port 27016 `
    +sv_lan 1 +rcon_password 'ПАРОЛЬ_ВТОРОГО_СЕРВЕРА' +game_type 0 +game_mode 2 +map de_inferno
```

Первый процесс остаётся на `27015`; второй добавьте в панели отдельно с портом `27016`. Если используете GOTV, задайте каждому процессу свой `+tv_port`. Проверьте одновременную работу процессов и плагина на своём ПК перед турниром.

Панель считает добавленные серверы своими: перед загрузкой следующего матча она отправляет `get5_endmatch`. Не используйте эти процессы одновременно для ручных матчей. При автоматическом запуске панель ищет свободный сервер, передаёт ему конфигурацию матча по RCON и ждёт подтверждения от ArenaPro. После завершения серии плагин отправляет результат панели. Если сервер не подтвердил загрузку, матч снова становится готовым к запуску, а сервер временно исключается из раздачи.

### Если сервер не отвечает

- Проверьте, что `cs2.exe` запущен, IP и порт в панели совпадают с параметрами процесса, а RCON-пароль введён верно.
- Проверьте доступность `PUBLIC_URL` с компьютера игрового сервера и правила брандмауэра для порта панели.
- После обновления CS2 проверьте совместимость Metamod, CounterStrikeSharp и ArenaPro; подключитесь к тестовому матчу до турнира.

## Работа в панели

**Администратор** входит с локальным логином и паролем. В «Картах» он управляет библиотекой карт; стандартные карты добавляются при первом запуске с пустой базой. В «Серверах» добавляет процессы CS2. На странице «Турниры» создаёт турнир, выбирает команды, карты и формат, затем начинает турнир. Доступны ручной запуск матча на сервере и ввод результата. При включённом автозапуске готовые матчи распределяются по свободным серверам.

**Игрок** входит через Steam, создаёт команду или вступает в неё по коду приглашения. Для входа через Steam нужен интернет. Капитан регистрирует команду в открытом турнире. Если включено вето карт, капитаны делают ходы на странице матча до его отправки на сервер. После запуска на главной странице игрока появляется команда подключения вида `connect 192.168.0.4:27015`.

Поддерживаются сетки single и double elimination, а также круговой, швейцарский и GSL групповые этапы. Для групп можно включить последующий плей-офф. Настройки серии BO1/BO3/BO5 и вето задаются при создании турнира.

## Текущие ограничения

- Автоматическая обработка полной серии на реальном сервере, Workshop-карты и режим 1v1 не проверены сквозным игровым тестом. Перед турниром проведите пробный матч на своей конфигурации.
- Панель не собирает демозаписи. Их запись зависит от настройки ArenaPro.
- Панель рассчитана на локальную сеть: в проекте нет настройки HTTPS и защиты входа администратора от перебора пароля. Не публикуйте её напрямую в интернете.
- Число одновременных серверов зависит от оборудования и режима матчей; нагрузку нужно проверить на конкретном ПК. Каждый параллельный матч требует отдельного процесса CS2.

## Разработка

```powershell
npm.cmd run dev:server     # API с перезапуском при изменениях
npm.cmd run dev:web        # Vite на порту 5173
npm.cmd run build          # сборка панели
npm.cmd test -w server     # тесты сеток, групп и вето
npm.cmd run plugin:test    # тесты ArenaPro; нужен .NET SDK
npm.cmd run plugin:build   # пакет ArenaPro в plugin-dist/
```

Серверная часть находится в `server/src/`, интерфейс и переводы — в `web/src/`, исходники ArenaPro — в `plugin/`. Скрипт установки плагина — `scripts/build-plugin.ps1`.

`global.json` выбирает стабильный .NET SDK 10 с установленным обновлением. В `package.json` закреплены исправленные версии `glob/minimatch`, пока `@fastify/static` использует более старую ветку, и разрешён установочный скрипт `esbuild@0.28.2`, необходимый сборке. При обновлении esbuild нужно пересмотреть это разрешение. Проверка зависимостей: `npm.cmd audit` и `dotnet list plugin/ArenaPro.csproj package --vulnerable --include-transitive`.

Если NuGet-зависимости уже восстановлены, пакет плагина можно собрать без обращения к NuGet: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-plugin.ps1 -NoRestore`. При ошибке сборки предыдущий пакет `plugin-dist` сохраняется.
