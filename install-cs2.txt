УСТАНОВКА СЕРВЕРА CS2, ПАНЕЛИ ТУРНИРОВ И ARENAPRO ДЛЯ WINDOWS

Файл установки: install-cs2.ps1 (в корне проекта).
Скрипт предназначен для нового сервера в локальной сети на Windows x64.
Запускать нужно на компьютере, где уже установлена CS2 через Steam.
Для установки необходимы интернет и Windows PowerShell 5.1 x64 или PowerShell 7 x64.
Steam, клиент CS2 и его файлы скрипт не устанавливает и не изменяет.

БЫСТРЫЙ ЗАПУСК

1. Скачайте только install-cs2.ps1 на нужный компьютер. Исходники проекта
   и заранее установленные Git, Node.js и .NET не нужны: скрипт загрузит их сам.
   Репозиторий: https://github.com/nfilatoff/cs2tournamentorganizator
   Прямая ссылка на скрипт:
   https://raw.githubusercontent.com/nfilatoff/cs2tournamentorganizator/main/install-cs2.ps1

2. Откройте PowerShell в папке со скачанным скриптом и выполните проверку:

   powershell -NoProfile -ExecutionPolicy Bypass -File .\install-cs2.ps1 -CheckOnly

   Проверка ничего не скачивает, не создаёт папки и не меняет настройки.
   Права администратора для проверки не нужны.

3. Откройте PowerShell x64 от имени администратора и выполните:

   powershell -NoProfile -ExecutionPolicy Bypass -File .\install-cs2.ps1

   Права администратора нужны для Microsoft Visual C++ Redistributable,
   настройки брандмауэра и ограничения доступа к файлам с паролями.
   Скрипт сам не повышает привилегии и не меняет ExecutionPolicy системы.

   Без -InstallRoot скрипт предложит ввести папку или диск. Например:
   E:\LAN Server, E: или E. Пустой ввод выбирает <диск CS2>:\CS2Tournament.
   В режиме -CheckOnly запросов ввода нет: используется -InstallRoot или
   папка по умолчанию. Для проверки выбранного пути укажите его явно:

   powershell -NoProfile -ExecutionPolicy Bypass -File .\install-cs2.ps1 -InstallRoot 'E:\LAN Server' -CheckOnly

   Для установки в этот же каталог уберите -CheckOnly.

КАК ВЫБИРАЕТСЯ ДИСК И ПРОВЕРЯЕТСЯ МЕСТО

Скрипт читает пути Steam из реестра и библиотеки из libraryfolders.vdf.
В библиотеках он ищет appmanifest_730.acf и настоящий game\bin\win64\cs2.exe.
Учитываются библиотеки Steam на других дисках, а не только системная папка Steam.
Если найдено несколько установок CS2 или ни одной, скрипт остановится и попросит
явно указать -Cs2Path. Можно передать каталог игры или полный путь к cs2.exe.

По умолчанию сервер, панель, инструменты, кэш и временные файлы размещаются в
<диск с установленной CS2>:\CS2Tournament. Например, для CS2 на E: это
E:\CS2Tournament. Сервер скачивается SteamCMD отдельно от игрового клиента.
Папка сервера не может находиться внутри папки клиента CS2 или содержать её.

До создания каталогов, загрузок и установки скрипт проверяет доступное место.
Нужно не менее 120 ГиБ свободного места на диске CS2. Если в манифесте клиента
указан большой SizeOnDisk, требование повышается до большего значения из:
120 ГиБ и (размер установленной игры * 1,2 + 20 ГиБ).
Это резерв для отдельной копии игры, инструментов, архивов и сборки.
Можно повысить минимум: -RequiredFreeGB 180. Понизить ниже 120 нельзя.
Перед SteamCMD дополнительно проверяются 100 ГиБ, после него — 8 ГиБ.
Если Windows находится на другом диске, на нём дополнительно нужны 2 ГиБ
для системной установки Visual C++ Redistributable.

При нехватке места выводятся диск, необходимый и доступный объём и недостающее
место; скрипт завершается с кодом 1. Другой диск автоматически не выбирается.
Объём будущих обновлений Steam заранее не гарантирован: если игра вырастет или
место займёт другая программа, ошибка SteamCMD/записи также прерывает установку.
При отказе начальной проверки ничего не устанавливается. Ошибки поздних этапов
оставляют уже скачанные файлы и установленные компоненты; повторный запуск
продолжит с места остановки.

-InstallRoot позволяет указать другую НОВУЮ/ПУСТУЮ папку на том же диске.
Если указана только буква диска, например -InstallRoot 'E:', будет выбрана
папка E:\CS2Tournament. Выбор другого диска относительно CS2 отклоняется.
Репозиторий клонируется в подпапку panel выбранной папки установки;
сервер располагается рядом в подпапке cs2.
Посторонняя непустая папка не используется и не перезаписывается. Но папка
прошлой установки этого скрипта (есть logs\install.log или installation.json)
принимается: см. раздел «ПОВТОРНЫЙ ЗАПУСК».
UNC-пути, сетевые и съёмные диски, SUBST, junction, символические ссылки и
смонтированные папки в пути игры/установки не поддерживаются: используйте
прямой путь с буквой физического локального диска.

ПОВТОРНЫЙ ЗАПУСК (ПРОВЕРКА И ДОУСТАНОВКА)

Скрипт можно запускать повторно с тем же -InstallRoot (или с тем же диском CS2
и папкой по умолчанию). Он ничего не ставит заново вслепую: сначала определяет,
что уже есть, печатает таблицу OK / MISSING и выполняет только недостающее.
Проверяются: MinGit, клон проекта, Node.js 24, .NET SDK 10, VC++ runtime (реестр),
SteamCMD, серверная CS2 (манифест StateFlags=4), Metamod, CounterStrikeSharp,
сборка панели (node_modules, server\dist, web\dist), плагин ArenaPro, конфиг
сервера, база панели, файлы запуска, правила брандмауэра (по именам).

   - Установленные компоненты пропускаются, без повторных загрузок.
   - Остатки прерванного шага (неполный клон, распакованный архив) удаляются
     только внутри папки установки и шаг выполняется заново.
   - Прерванная загрузка CS2 продолжается через SteamCMD (app_update ... validate).
   - Существующая база панели, пароль admin и RCON не меняются; credentials.txt
     не перезаписывается. Если нет конфига сервера, RCON берётся из credentials.txt.
   - Адрес и порты берутся из installation.json. Другие значения параметров
     игнорируются с предупреждением: они уже записаны в базе, правилах и запуске.
   - Проект (panel\) из GitHub не обновляется, локальные правки сохраняются.
   - gameinfo.gi проверяется всегда: после обновления CS2 в Steam Metamod
     включается снова.
   - Требование 120 ГиБ свободного места действует, только если серверная CS2
     ещё не установлена (или указан -UpdateGame).
   - -UpdateGame: принудительно запустить SteamCMD app_update 730 validate,
     чтобы обновить/проверить файлы сервера. Останавливайте сервер перед этим.
   - -CheckOnly на существующей установке ничего не меняет и только показывает
     таблицу компонентов.
   - Права администратора по-прежнему нужны для любого не-CheckOnly запуска.
   - Лог install.log дополняется (-Append), а не затирается.

ПРИМЕРЫ ПАРАМЕТРОВ

Явный путь к CS2 и сетевой адрес компьютера:

   .\install-cs2.ps1 -Cs2Path 'E:\SteamLibrary\steamapps\common\Counter-Strike Global Offensive' -ServerAddress '192.168.1.20'

Своя папка установки на том же E: и другие порты:

   .\install-cs2.ps1 -Cs2Path 'E:\SteamLibrary\steamapps\common\Counter-Strike Global Offensive' -InstallRoot 'E:\LAN Server' -ServerAddress '192.168.1.20' -ServerPort 27016 -PanelPort 3100 -TvPort 27021

Порты по умолчанию: игровой сервер/RCON 27015, панель 3000, GOTV 27020.
Эти три номера должны различаться. Выбирайте свободные порты.
ServerAddress — реальный IPv4 этого компьютера в локальной сети.
Без этого параметра выбирается единственный IPv4 активного адаптера со шлюзом.
Если подходят несколько адаптеров (например, VPN и Ethernet), укажите адрес явно.

ИСТОЧНИКИ ПРОЕКТА И GITHUB

Скрипт всегда клонирует публичный репозиторий:

   https://github.com/nfilatoff/cs2tournamentorganizator.git

Адрес уже записан в install-cs2.ps1, вводить его при обычном запуске не нужно.
Исходники рядом со скриптом не используются; параметр -SourcePath удалён.
Сам установщик не публикует файлы и не отправляет локальные изменения на GitHub.
При необходимости можно установить другой публичный форк:

   .\install-cs2.ps1 -RepositoryUrl 'https://github.com/OWNER/REPOSITORY.git'

OWNER/REPOSITORY нужно заменить реальным публичным репозиторием ЭТОГО проекта,
включающим панель и изменённый ArenaPro. Исходный MatchZy для этого не подходит.
Ветка/тег по выбору: -RepositoryBranch 'main'. Без параметра — ветка по умолчанию.
Установщик скачивает официальный portable MinGit x64 и выполняет git clone.
Заранее установленный Git, токены и вход в GitHub не нужны для публичного проекта.
URL должен иметь вид https://github.com/владелец/репозиторий без учётных данных.
Не указывайте непроверенные репозитории: при сборке выполняется их код.

ЧТО УСТАНАВЛИВАЕТСЯ

1. Portable MinGit x64 и git clone --depth 1 из опубликованного репозитория
   в <папка установки>\panel. При -RepositoryBranch клонируется указанная ветка
   или тег; иначе используется ветка репозитория по умолчанию.
   Данные существующей панели и её аккаунты в новую установку не переносятся.
2. Последний Node.js ветки 24 для Windows x64 с официального nodejs.org.
   SHA256 архива проверяется по официальному SHASUMS256.txt.
3. Стабильный .NET SDK ветки 10.0 через официальный dotnet-install.ps1 Microsoft.
   Node.js и .NET размещаются внутри tools, системный PATH не изменяется.
4. Microsoft Visual C++ Redistributable x64 через официальный установщик Microsoft.
   Проверяется действительная цифровая подпись Microsoft. Перезагрузка автоматически
   не выполняется; если установщик её требует, выводится предупреждение.
5. SteamCMD с CDN Valve и отдельная CS2 через anonymous/app_update 730 validate.
   Скачивание игры может быть длительным. Проверяются код возврата, сообщение
   SteamCMD об успешной установке и наличие серверного cs2.exe.
6. Metamod:Source 2.x для Windows, сборка не ниже 1467 с KHook, с официальной страницы
   master. CounterStrikeSharp сейчас требует эту ветку, а не старую 1.12.
   Последний CounterStrikeSharp with-runtime для Windows с GitHub разработчика,
   не ниже 1.0.379 — версии API, используемой этим ArenaPro. Встроенный runtime
   нужен для загрузки плагина и устанавливается вместе с CounterStrikeSharp.
   GitHub-архивы проверяются по SHA256 digest, когда API возвращает его.
   gameinfo.gi получает Game csgo/addons/metamod в начале SearchPaths;
   оригинал сохраняется как gameinfo.gi.before-arenapro.
7. npm ci по package-lock.json, сборка панели и сборка ArenaPro через существующий
   scripts/build-plugin.ps1. Плагин, конфиги и gamedata копируются на сервер.
8. Конфигурация LAN, случайные пароли администратора и RCON, база SQLite с
   администратором admin и уже добавленным игровым сервером, файлы запуска.
   Панель сама передаёт ArenaPro адрес событий и токен при запуске матча.

ПРАВА ДОСТУПА И СЕТЬ

Каталог установки доступен текущему пользователю Windows, группе администраторов
и SYSTEM; обычные другие пользователи компьютера доступа не получают.
Пароли находятся в credentials.txt; RCON также в конфиге сервера и базе панели.
Пароли не передаются в командной строке и не выводятся в журнал установки.
Запускайте панель и сервер от той же учётной записи Windows, которая их установила.

По умолчанию создаются входящие правила Windows Firewall для панели TCP,
RCON TCP, игры UDP и GOTV UDP. Разрешены только LocalSubnet и профили
Private/Domain, с ограничением по конкретному исполняемому файлу.
В публичном профиле сети эти правила не действуют. Если правилами управляете
самостоятельно, используйте -SkipFirewall. Это не отменяет необходимость
прав администратора для установки VC++ и настройки прав каталогов.
Маршрутизатор и переадресация портов не настраиваются.

КАК ЗАПУСКАТЬ ПОСЛЕ УСТАНОВКИ

В конце скрипт печатает точные пути. Например, для установки на E: откройте
два терминала PowerShell от той же учётной записи Windows:

   powershell -NoProfile -ExecutionPolicy Bypass -File 'E:\CS2Tournament\start-panel.ps1'

   powershell -NoProfile -ExecutionPolicy Bypass -File 'E:\CS2Tournament\start-server.ps1'

Для остановки используйте Ctrl+C в соответствующем терминале.
Альтернатива — start-all.ps1: запускает оба процесса в фоне со скрытыми окнами;
вывод идёт в logs\start-panel.ps1.out.log / .err.log и аналогичные файлы сервера.
Фоновые процессы можно остановить через Диспетчер задач: node.exe установленной
панели и выделенный cs2.exe сервера. Учитывайте другие запущенные приложения
Node.js и клиент игры: останавливайте только процессы с нужными путями.
Не запускайте start-all.ps1 повторно поверх уже работающей установки.

Установка сама не запускает процессы, службы и задания автозапуска не создаёт.
Сервер настроен на LAN: -insecure, sv_lan 1, -usercon, de_inferno, game_mode 2.
GSLT для этого LAN-режима не запрашивается. Публичный интернет-сервер требует
отдельной настройки Steam/VAC/GSLT, адресов и сетевой безопасности.

Откройте адрес панели из credentials.txt, войдите как admin с созданным паролем
и смените пароль в разделе аккаунта. После смены запись Initial password в
credentials.txt не обновляется. Сервер уже есть в разделе «Серверы».
Проверьте его связь кнопкой проверки после запуска CS2.
В консоли игрового сервера выполните meta list и css_plugins list:
должны быть загружены CounterStrikeSharp и ArenaPro. Перед турниром проведите
тестовый матч: установщик не заменяет проверку совместимости после обновлений CS2.

ФАЙЛЫ И ДИАГНОСТИКА

В папке установки:
   cs2\                отдельная серверная CS2;
   panel\              исходники, зависимости и собранная панель;
   tools\              Node.js, .NET SDK, SteamCMD и MinGit;
   data\app.db         новая база панели;
   installation.json   адрес и порты для файлов запуска;
   credentials.txt     начальные пароли и адреса;
   downloads\          загруженные архивы и установщики;
   cache\, temp\       кэш сборки и временные файлы;
   logs\install.log    общий журнал установки;
   logs\steamcmd.log   подробный вывод SteamCMD.

При ошибках сети загрузки повторяются до трёх раз; ошибки сборки и установки
прерывают сценарий с кодом 1. Успешная установка и -CheckOnly возвращают код 0.
Автоматического отката нет: уже установленный системный VC++ и созданные правила
брандмауэра сохраняются, если ошибка произошла на более позднем этапе.
Для резервной копии остановите панель и сохраните папку data; настройки сервера
и пароли также сохраняйте отдельно. Не публикуйте папку установки в GitHub.

OFFLINE-ПРОВЕРКИ САМОГО УСТАНОВЩИКА

   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-installer.ps1

Эти проверки используют временные фикстуры внутри проекта, затем удаляют их.
Нужен Git для теста клонирования из временного локального репозитория.
Проверяются синтаксис, выбор папки и диска, пути с пробелами, клон ветки/тега,
оценка места, отмена установки без создания целевой папки, отказ при выборе
другого диска, патч gameinfo и пароли. При наличии собранной панели и Node.js
также проверяется создание SQLite с администратором и игровым сервером.
Интернет для этих проверок не нужен; игру они не скачивают и не запускают.
